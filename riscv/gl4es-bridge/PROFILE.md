# Measuring the gl4es boundary

Configure the bare-metal engine with `-DBAREMETAL_SHIM_PROFILE=ON`. This is an
opt-in diagnostic build; normal builds have no boundary wrappers or allocation
table. Also enable the normal render profiler so each present emits a report.

The generator reads the local desktop GL and GLES declarations and produces
typed wrappers. The SDL resolver is wrapped at link time; all 136 GLES entries
returned by the bridge are wrapped separately. Uncovered desktop entry points
print `[shim-unwrapped]` and must be assessed before interpreting measurements.

`[shim] exclusive_us` sums outer desktop API elapsed time minus GLES time nested
inside those calls. This measures gl4es work, including its conversion helpers
and allocator cost, but excludes downstream software rendering and shader
compilation. Nested GLES calls are counted once. `inclusive_us` includes that
downstream work. `driver_us` also includes GLES calls outside the desktop API
spans, so subtracting the two **frame totals** is not valid. The exclusive
subtraction happens independently inside each desktop call.

These are guest `rdtime` wall-clock measurements, not hardware cycle counts or
aggregate CPU time across eight harts. Under QEMU they include host scheduling
variation. Diagnostic hooks add overhead; small exclusive figures are an
instrumented estimate, not a calibrated native-hardware latency. Deferred raster
work at presentation is not charged to gl4es. The cost of executing shaders
generated by gl4es belongs to softgles2 in this accounting; changes to generated
shaders could still improve that downstream cost.

For memory, objcopy remaps malloc/calloc/realloc/free/strdup references in a
**copy** of the gl4es archive. The original archive is untouched. A fixed table
tracks requested live bytes and high-water marks without adding allocation
headers. It excludes renderer allocations, allocator metadata/fragmentation and
library static sections. Its own roughly 2 MiB table is printed separately.
Require `untracked_frees=0`, `overflow=0`, and `depth=0` in measured frames.
Allocation counts include realloc bookkeeping; byte totals measure allocation
traffic, not memory bandwidth or retained memory.

Validate the accounting independently:

```powershell
python riscv/gl4es-bridge/test/run_profile_validate.py
```

Run QEMU, let the map and shaders settle, fix the camera/time using
`riscv/scripts/visual_probe.py`, and capture a screenshot. Exclude the capture
frame and warm-up frames from timing. Summarize a completed contiguous range
using the **shim frame numbers**, which also count loading-screen presents:

```powershell
python riscv/gl4es-bridge/profile_analyze.py path/to/run.log --first 44 --last 53 --output path/to/results.json
```

Restore `-DBAREMETAL_SHIM_PROFILE=OFF` and rebuild before measuring normal
production performance.
